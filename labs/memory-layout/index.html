EXPERIMENT 02 / STRUCT OVERLAY

One record. Twelve bytes.

A separate byte-level demo uses DataView to overlay different field types on the very same 12 bytes. Here we deliberately choose little-endian storage and explicit padding.

struct Fish {
float x; // 4 bytes
uint8_t hp; // 1 byte
/* padding */ // 3 bytes
float y; // 4 bytes
};
Compare with your native C compiler · sizeof / offsetof

Native C records may have different padding, alignment and total size. Run the companion C17 experiment in WSL or your native compiler to inspect sizeof, _Alignof and offsetof on that platform.

cc -std=c17 pilot/labs/struct_layout_demo.c -o struct_layout_demo && ./struct_layout_demo

Open C17 companion source ↗

Important: the pictured 12-byte layout is a deliberate DataView encoding, not a guaranteed C struct layout. Native alignment and padding vary by ABI, compiler and packing settings. JS object properties do not imply this memory layout either.

EXPERIMENT 03 / TRADE-OFF

When does each layout help?

All three models use Float32Array values. For SoA, each field uses a separate independently allocated buffer; for AoS and AoSoA, this example allocates a single buffer. Actual base addresses, cache lines and physical RAM placement cannot be inspected by standard browser JavaScript.
